# Лабораторная 05 — ORM-демо «Students»

**Задание:** «Используя подход ORM, реализовать таблицы в виде классов».

Ядро работы — `models.py`: пять таблиц описаны классами SQLAlchemy 2.x (`DeclarativeBase`,
`Mapped`, `mapped_column`, `relationship`). Вокруг него собрано живое демо: бэкенд на FastAPI
работает с БД **только через ORM-классы** (без ручного SQL), фронтенд на SvelteKit позволяет
выполнять все действия с данными в браузере.

## Архитектура

```
Браузер (SvelteKit SPA)
    │  HTTP/JSON (/api/...)
    ▼
api.py (FastAPI) ──► Swagger-документация: /docs
    │  session.add / session.get / select(...) — только ORM
    ▼
models.py (ORM-классы: Student, Group, Course, StudentCard, StudentCourse)
    │  SQLAlchemy сам генерирует SQL
    ▼
MySQL 8.4, база students_orm
```

Связи в модели:
- `Group 1:N Student` (при удалении группы у студентов `group_id = NULL`);
- `Student 1:1 StudentCard` (билет удаляется вместе со студентом);
- `Student N:M Course` через ассоциативную таблицу `students_courses`.

## Файлы

| Файл | Назначение |
|---|---|
| `models.py` | ORM-модели — ядро задания (файл преподавателя; исправлен только баг `Mapped[datetime.date]` → `Mapped[date]`) |
| `start.py`, `start.cmd` | Лаунчер: запуск всего демо одной командой (или двойным кликом) |

| `CRUD.py`, `fillDatabase.py` | Прошлая лабораторная (чистый SQL, база `students`) — оставлены нетронутыми для справки |

## Требования

- Python 3.10+ (проверено на 3.15), пакеты: `pip install -r requirements.txt`
- Node.js 22+ (для сборки фронтенда), зависимости: `cd frontend && npm install`
- MySQL 8 (на этой машине установлен как служба **MySQL84**, пользователь `root` без пароля)

## Запуск

**Одной командой:** `python start.py` (или двойной клик по `start.cmd`).

Лаунчер сам выполняет всю рутину:
1. Проверяет MySQL (служба `MySQL84`, автозапуск вместе с Windows); если остановлена — запускает (может запросить UAC).
2. Создаёт БД `students_orm` и таблицы, если их нет; заполняет тестовыми данными, **только если база пуста** — данные сохраняются между запусками.
3. Собирает фронтенд, если он ещё не собран или исходники изменились (при необходимости ставит npm-зависимости).
4. Запускает сервер и открывает браузер: **http://127.0.0.1:8000**.

Остановка — `Ctrl+C` в терминале. Повторный запуск безопасен: если сервер уже работает,
лаунчер просто откроет браузер; если порт 8000 занят чужим процессом — сообщит об этом.

**Режим разработки (hot-reload):** `python start.py --dev` — бэкенд на 8000 плюс
SvelteKit dev-сервер (порт 5173, а если он занят — следующий свободный; фактический адрес
лаунчер читает из вывода Vite и открывает сам). Правки фронтенда применяются мгновенно,
без пересборки. Остановка — `Ctrl+C` (гасит оба процесса).

**Принудительная перегенерация данных:** `python start.py --reseed` или кнопка «↻ Пересоздать данные» в UI.

**Публичный доступ из интернета (туннель):** `python start.py --tunnel`.
Нужна разовая установка cloudflared: `winget install Cloudflare.cloudflared`.
Лаунчер поднимет сервер и туннель Cloudflare и выведет публичный HTTPS-адрес вида
`https://xxx.trycloudflare.com` — его можно открыть с любого устройства в интернете
(например, с другого компьютера или телефона). Особенности:
- адрес временный: меняется при каждом перезапуске туннеля;
- ПК должен быть включён и не засыпать;
- в приложении нет авторизации — любой, у кого есть ссылка, может менять данные;
- наружу пробрасывается только порт 8000; MySQL остаётся локальным.

Swagger-документация API: **http://127.0.0.1:8000/docs**.

### Ручной запуск (если хочется по шагам)

```
net start MySQL84          # если служба остановлена
python seed.py             # только при пустой базе
python api.py              # сервер на 8000, раздаёт собранный фронтенд
```

Пересборка фронтенда после правок: `cd frontend && npm run build`
(перезапуск сервера не нужен — статика читается с диска).
После изменения `api.py`/`models.py` сервер перезапустить вручную.

## Тесты

При работающем сервере: `python test_api.py` — проверяет статистику, полный CRUD-цикл
(студент → билет → курс → запись на курс → удаление), ограничения (возраст ≥ 16,
уникальность имён, один билет на студента, составной PK записи) и раздачу фронтенда.

## Возможности демо

- **Студенты:** поиск по имени/email, фильтр по группе, пагинация, добавление/изменение/удаление.
  Клик по строке раскрывает детали: студенческий билет (выдать/удалить) и курсы (записать/отписать).
- **Группы:** создание, переименование, удаление (студенты остаются без группы), счётчики.
- **Курсы:** CRUD с ценой и описанием, счётчики записанных студентов.
- **Статистика** и кнопка полной перегенерации тестовых данных.
- Ошибки ограничений БД (CHECK, UNIQUE, FK) показываются в интерфейсе как есть.

## Примечания

- Названия курсов в `seed.py` укорочены до 20 символов — ограничение `String(20)` из `models.py`.
- База `students_orm` создаётся автоматически при первом запуске `seed.py`/`api.py`
  (`create_all`), сама БД должна существовать (уже создана на этой машине).
- Подключение: `mysql+pymysql://root:@127.0.0.1:3306/students_orm` (учебная среда, root без пароля).
